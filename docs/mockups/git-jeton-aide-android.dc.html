Créer un jeton d’accès

OpenDives se connecte à votre dépôt avec un jeton d’accès personnel, jamais avec votre mot de passe. Créez un jeton limité à ce seul dépôt, avec le droit de lire et d’écrire son contenu et rien d’autre, et une date d’expiration. Les libellés ci-dessous sont ceux de l’interface anglaise de chaque site.

GitHub

Un jeton « fine-grained » peut être limité à un seul dépôt.

  1. Connectez-vous à GitHub, puis ouvrez Settings (menu de votre photo de profil).
  2. Tout en bas de la colonne de gauche, ouvrez Developer settings.
  3. Ouvrez Personal access tokens, puis Fine-grained tokens, puis touchez Generate new token.
  4. Token name : un nom reconnaissable, par exemple OpenDives.
  5. Expiration : choisissez une date proche, par exemple dans 90 jours. À cette date le jeton cesse de fonctionner et vous en créez un nouveau.
  6. Resource owner : votre compte, ou l’organisation qui possède le dépôt.
  7. Repository access : choisissez Only select repositories, puis le dépôt de votre carnet.
  8. Permissions : dans Repository permissions, réglez Contents sur Read and write. N’ajoutez aucune autre permission.
  9. Touchez Generate token, puis copiez le jeton.

GitLab

Un jeton de projet est limité à un seul projet. Sur GitLab.com il demande l’offre Premium ou Ultimate (toute licence sur un serveur GitLab auto-hébergé) et le rôle Maintainer ou Owner sur le projet. Sans cela, utilisez un jeton personnel, qui donne accès à tous vos projets : GitLab ne permet pas de le limiter à un seul.

Jeton d’accès de projet (project access token)

  1. Ouvrez votre projet, puis dans la colonne de gauche Settings, Access tokens.
  2. Touchez Add new token.
  3. Token name : un nom reconnaissable, par exemple OpenDives.
  4. Expiration date : une date proche (365 jours au plus).
  5. Rôle : le plus bas qui permet d’envoyer vos modifications sur la branche, Developer, ou Maintainer si la branche est protégée.
  6. Scopes : cochez write_repository seulement.
  7. Touchez Create project access token, puis copiez le jeton.

Sinon, jeton d’accès personnel (personal access token)

  1. En haut à droite, touchez votre avatar, puis Edit profile.
  2. Dans la colonne de gauche, ouvrez Access, puis Personal access tokens.
  3. Dans la liste Generate token, choisissez Legacy token.
  4. Token name : un nom reconnaissable. Expiration date : une date proche.
  5. Scopes : cochez write_repository seulement.
  6. Touchez Generate token, puis copiez le jeton.

Dans OpenDives, le nom d’utilisateur est le vôtre sur GitLab. Pour Git en HTTPS, GitLab accepte tout nom non vide avec le jeton.

Codeberg

Le guide de Codeberg précise qu’un jeton donne par défaut un accès complet à votre compte : limitez-le comme ci-dessous.

  1. Connectez-vous à Codeberg, ouvrez le menu de votre photo de profil (Profiles and Settings), puis Settings.
  2. Ouvrez l’onglet Applications.
  3. Sous Manage Access Tokens, dans Generate New Token, saisissez un Token Name reconnaissable, par exemple OpenDives.
  4. Si le formulaire le propose, limitez le jeton à votre dépôt : choisissez Specific repositories, puis le dépôt de votre carnet.
  5. Permissions : pour repository, choisissez Read and Write. Laissez les autres sur No access.
  6. Si le formulaire propose une date d’expiration, choisissez une date proche. Le guide de Codeberg n’en parle pas : sans date, supprimez le jeton depuis cette page quand vous ne l’utilisez plus.
  7. Touchez Generate Token, puis copiez le jeton.

Collez ensuite le jeton dans OpenDives, avec votre nom d’utilisateur. Le jeton n’est montré qu’une fois par le site : copiez-le avant de quitter la page.
